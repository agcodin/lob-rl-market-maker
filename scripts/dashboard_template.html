A PPO agent posts a buy and a sell quote every tick and gets paid the spread when both sides fill. Its real problem is inventory: every unfilled share it holds is a directional bet it never meant to make. This page replays one held-out episode the agent never trained on, tick by tick, and shows what it learned to do about that.

What it learned: inventory skew

Mean distance from the mid price the agent placed each quote, grouped by the position it was holding at the time.

bid offset — how far below mid it will buy ask offset — how far above mid it will sell

Nobody told the agent this rule. It has no notion of "inventory risk" — only a reward that subtracts φq² every step it holds a position.

From that alone it derived the market maker's reflex: when it is long, it drops its ask on top of the market and pulls its bid away — attractive to buyers, unattractive to sellers, so the next fill is more likely to flatten it than deepen it. When short, exactly mirrored.

This is the same behaviour the closed-form Avellaneda–Stoikov quoter gets by construction, arrived at from scratch by gradient descent on PnL.

Each arm is compared in paired episodes: both policies quote into the same book on the same seed, seats alternating, so the shared market noise cancels. Arm C — the learner taking every seat, which is closest to plain self-play — is the control: it received the same extra transitions as the others and produced nothing, so the gain is not simply more training.

Where that leaves everything

What you are looking at

A C++20 matching engine (4–7 ns per order operation, no heap allocation on the hot path) driving a synthetic market: Poisson passive flow, queue-dependent cancellations, Hawkes-clustered aggressive orders and power-law trade sizes. The agent sees the top 5 book levels, imbalance, its own position, volatility and queue position, and outputs two numbers — how far below and above the mid to quote.

Reward: R = ΔPnL − φq² − η(Δq)² — the Avellaneda–Stoikov utility, with φ penalizing held inventory and η penalizing churn.

Reproduce

make install
make test          # 28 engine + env tests
make bench         # latency percentiles
make train         # 1.2M steps, ~5 min CPU
make eval          # this comparison table
  • The market is synthetic — these Sharpe numbers describe this simulator, not a real venue.
  • Baselines run on identical seeds, so the comparison is like for like.
